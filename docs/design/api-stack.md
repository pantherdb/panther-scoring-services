# API Stack

**Status:** Proposed, 2026-10-28. Split out of [tech-stack.md](tech-stack.md), which stays Proposed for the API's architecture (jobs, compatibility endpoints, versions in responses) and for the engine.

## Decision

FastAPI was agreed in [tech-stack.md](tech-stack.md): it's the engine's language, and it generates the OpenAPI schema that is the frontend ↔ api contract. This doc fixes the tools around it.

| Concern | Choice | Why |
| ------- | ------ | --- |
| Framework | FastAPI 0.162 (`fastapi[standard-no-fastapi-cloud-cli]`): Starlette, Pydantic 2, uvicorn, the `fastapi` CLI | Same language as the engine; request validation and the OpenAPI schema come from the type hints. The `standard` extra without the cloud CLI, which we don't use |
| Packages and Python | uv 0.13; Python 3.13 | One fast tool for the Python install, the virtualenv, dependencies and the lockfile. 3.13 is current and well supported by the packages we use |
| Settings | pydantic-settings 2.16 | Typed configuration from environment variables, validated at start-up. Added with the first setting, not before |
| Lint and format | Ruff 0.17, with the `S` (security) and `FAST` (FastAPI) rules on | One tool replaces black, flake8, isort and pyupgrade. The `S` rules flag `subprocess` with `shell=True`, which enforces "never pass request data through a shell" (`CGI-5`) |
| Type checker | basedpyright 1.40, strict mode | Same engine as VS Code's Pylance, so the editor and CI report the same errors. Checks Pydantic models without a plugin. Installs as a normal Python package, without the Node download the `pyright` package needs |
| Editor | VS Code with the basedpyright extension instead of Pylance | The extension runs the same checker and rules as CI |
| Tests | pytest 9 with FastAPI's `TestClient` | Tests the app through HTTP requests, without starting a server |
| Error responses | RFC 9457 problem details (`application/problem+json`) | One error shape for every endpoint, declared in the schema, so the frontend has one generated error type. FastAPI's default has two shapes under `detail` (a string or a list) |
| OpenAPI contract | `api/openapi.json` committed, regenerated by one command; a test fails when it's out of date | The frontend generates its types from the file, without running the API. Every contract change shows up as a schema diff in the API's pull request |
| Dev server | Port 8000; no CORS | The frontend proxies `/api` to `localhost:8000` and calls a same-origin `/api/v1` |

The scaffold pins the newest release in each of these lines, exactly. Moving to a new major, or adding a tool, is a change to this doc made through a proposal.

## Project Layout

`api/` is its own uv project, with its own `pyproject.toml`, `uv.lock` and `.python-version`. It is not part of a uv workspace shared with `engine/`.

- **Why:** the API can start, and its owner can change its setup, without touching `engine/` or the repo root.
- **How the engine joins:** once `engine/` has a package, `api/` adds it as a path dependency (`{ path = "../engine", editable = true }`). uv then resolves the engine's dependencies into `api/uv.lock`, which is the lock that ships.
- **Accepted risk:** the engine's own lock, used for its tests, can drift from `api/uv.lock`. Closing that gap, for example by running the parity tests under the API's lock in CI, is a later change.
- **Python:** the engine's `requires-python` must include 3.13 when it's wired in.

*Alternative:* a uv workspace at the repo root with `api/` and `engine/` as members and one lock. It keeps the versions that the engine is tested with and the versions that ship identical, but it needs the engine owner's sign-off on root files and a shared Python version before the engine exists. Rejected for now; moving to it later is a small change.

## Rules That Come With It

1. **Every route under `/api/v1`,** including the schema (`/api/v1/openapi.json`) and docs (`/api/v1/docs`), so the frontend's single `/api` proxy and a deployed site reach all of them.
2. **Errors are problem details.** Validation errors list the failing fields (`loc`, `msg`, `type`) and never echo what was submitted. Unexpected errors return a generic message; tracebacks and paths go to the log only.
3. **Regenerate `api/openapi.json` with every contract change,** in the same pull request.
4. **Strict types, no blanket ignores.** A `# pyright: ignore[rule]` names the rule and says why.
5. **No new dependencies without a proposal,** as for the frontend. Dependabot doesn't update Python packages; versions change through a proposal.

- The legacy compatibility endpoints.

- Whether `/api/v1/docs` is served in production. The working default is yes.
