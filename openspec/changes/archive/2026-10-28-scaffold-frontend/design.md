# Design

## Context

`frontend/` holds only `CLAUDE.md`. This change relies on these decisions and doesn't repeat them:

- The stack, why it's set up in full from day one, and how the parts fit: [docs/design/frontend-stack.md](../../../docs/design/frontend-stack.md).
- The folder layout, component rules, styling split, state rules and test rules: [frontend/CLAUDE.md](../../../frontend/CLAUDE.md).

The root `package.json` is only for OpenSpec. The frontend is its own npm project. Node 24 is in use locally.

## Goals / Non-Goals

**Goals:**

- Every convention in `frontend/CLAUDE.md` can be followed from the first feature on, without changing the setup.
- `npm run type-check && npm run lint && npm test` and `npm run test:e2e` all pass on the empty app.
- The first feature (the form) adds its endpoints, mock handlers and route without editing the store or the test setup.

**Non-Goals:**

- No scoring UI, API calls or OpenAPI type generation.
- No CI pipeline. That's a separate change once there is more than one area to build.
- No production hosting config (base path, server fallback for client-side routes).

## Decisions

### Layout

```text
frontend/
  package.json, index.html, vite.config.ts, vitest.config.ts, playwright.config.ts,
  tsconfig.json (+ tsconfig.app.json, tsconfig.node.json), eslint.config.js, .prettierrc
  public/mockServiceWorker.js          generated by `msw init`
  src/
    main.tsx                           providers: Redux -> Mantine -> Router; starts MSW in dev
    index.css                          layer order, Tailwind, @theme tokens
    app/
      store.ts                         configureStore with only the API reducer and middleware
      hooks.ts                         useAppSelector, useAppDispatch
      theme.ts                         Mantine theme
      router.tsx                       routes: "/" -> HomePage, "*" -> NotFoundPage
      api/api.ts                       createApi, no endpoints
    layout/AppLayout.tsx               header with title, <Outlet />
    features/home/                     HomePage.tsx, index.ts
    components/NotFoundPage.tsx        shared page, not a feature
    mocks/
      handlers.ts                      empty array
      browser.ts                       setupWorker(...handlers)
  tests/
    setup.ts                           jest-dom, reduced-motion matchMedia, MSW node server
    utils/render.tsx                   renders with the store, Mantine and a memory router
    app/store.test.ts
    layout/AppLayout.test.tsx
    app/router.test.tsx                home and not-found routes
  e2e/
    shell.spec.ts                      title, not-found, back to home, no horizontal scroll
```

### Features add their own endpoints to one API

`app/api/api.ts` creates the RTK Query API with no endpoints. Each feature adds its own with `api.injectEndpoints` in its own folder. All API calls still go through one API (one cache, one middleware), and each feature owns its endpoints.

- *Alternative:* one `createApi` per feature. Rejected: separate caches and middleware, and invalidation can't cross features.
- *Alternative:* every endpoint in `api.ts`. Rejected: one file every feature edits, against the feature-folder rule.

### Tests in separate folders

Vitest collects only `tests/**/*.test.{ts,tsx}` and Playwright only `e2e/`. `tests/` mirrors `src/` path for path. A shared `tests/utils/render.tsx` wraps components in the real store, theme and a memory router, so component tests use the same providers as the app.

### Three ways to run: mock, real API, site only

The app and the e2e suite both run in any of three modes, so nobody is blocked on the API and the site can be checked wherever it's deployed.

```text
                 API calls go to              started by
  mock      -->  MSW in the browser           npm run dev        / npm run test:e2e
  api       -->  real FastAPI via /api proxy  npm run dev:api    / npm run test:e2e:api
  site      -->  an already-running site      (none)             / E2E_BASE_URL=<url> npm run test:e2e:site
```

- **The app always calls a relative `/api/v1`.** Vite's dev and preview servers proxy `/api` to `API_PROXY_TARGET` (default `http://localhost:8000`). No API base URL is built into the bundle and there's no CORS setup; a deployed site serves `/api` from the same origin.
- **Mocking is one build-time flag, `VITE_API_MOCKING`** (`on` or `off`). When it's `on`, `main.tsx` starts the MSW worker before rendering. `dev` and `build:e2e` turn it on. `dev:api` and the normal `build` leave it off.
- **Site mode** sets `E2E_BASE_URL`. Playwright then starts no `webServer` and tests that URL as it is: a local preview, staging or production. Whatever API that site uses is the one tested.

**Which specs run in which mode.** Specs carry tags, and each `test:e2e*` script picks tags with `--grep` / `--grep-invert`:

| Tag | Needs | mock | api | site |
| --- | ----- | ---- | --- | ---- |
| (none) | nothing from the API | yes | yes | yes |
| `@mock` | specific mock data | yes | no | no |
| `@api` | a live API | no | yes | yes |

Every spec in this change is untagged, so the whole suite runs in all three modes.

### MSW: one list of handlers

`src/mocks/handlers.ts` is the only place handlers live. The dev server and the e2e build use it through the browser worker. Vitest uses it through `setupServer(...handlers)` in `tests/setup.ts`, with `onUnhandledRequest: 'error'` so an unmocked call fails the test. The list is empty in this change; the form adds the first handlers.

### Styling setup

- **CSS order:** `index.css` declares `@layer theme, base, mantine, components, utilities;`, imports `@mantine/core/styles.layer.css`, then Tailwind. Tailwind's base reset then can't override Mantine's component styles.
- **Colours come from one place.** Spike first: check whether Mantine 9 accepts CSS variables in `theme.colors`.
  - If it does, Tailwind's `@theme` holds the colours and `theme.ts` reads them as CSS variables, as `frontend/CLAUDE.md` already says.
  - If it doesn't, `theme.ts` holds the colours and `@theme inline` maps Tailwind's tokens onto Mantine's CSS variables (`--mantine-color-*`). Update `frontend/CLAUDE.md` to say so.

### Routing

React Router 7 in data mode (`createBrowserRouter`) with one layout route (`AppLayout`), an index route (`HomePage`) and a `*` route (`NotFoundPage`). Data mode leaves room for loaders and `/jobs/:id` later without restructuring.

### Playwright

- Two projects, `desktop` (Desktop Chrome) and `mobile` (Pixel 7).
- `baseURL` is `E2E_BASE_URL` when set (site mode, no `webServer`). Otherwise `webServer` builds for the mode (`build:e2e` for mock, `build` for api) and runs `npm run preview` on a fixed port, with `reuseExistingServer` off in CI.
- Specs wait for elements, never for `networkidle`, and assert on roles, not copy.

### Lint, format and TypeScript

As listed in `frontend/CLAUDE.md`. Two additions so its rules are enforced rather than remembered:

- `no-restricted-imports` blocks `useSelector` and `useDispatch` from `react-redux`.
- `@typescript-eslint/consistent-type-imports` enforces `import type`.

## Risks / Trade-offs

- [Mantine 9 and Tailwind v4 conflict over layers or the base reset] → The layer order above, and an e2e check that a Mantine button looks the same with and without Tailwind loaded (by screenshot, in the spike only, not kept as a test).
- [MSW in a production-mode build for e2e] → Mocking is controlled by a build-time flag that defaults to off. A normal `npm run build` never starts the worker; the e2e build turns it on explicitly.
- [Site mode run against production by accident with a destructive spec] → Specs in site mode only read; any future spec that submits jobs is tagged `@api` and reviewed for whether it's safe against a shared deployment.
- [Wrong mode chosen silently] → Each `test:e2e*` script prints its mode and target URL before running.
- [React Compiler with Vite 7] → Fall back to the compiler's opt-in mode if the build breaks, and record it in the tasks Notes.
- [Packages moving fast (Mantine 9, Vite 7, React Router 7)] → Pin exact versions in `package.json` and commit `package-lock.json`.
