# Divergences

Every deliberate difference between the Python engine and a service's reference. The format and rules are in [README.md](README.md). A row without an approver is a proposal: until it's signed off, the Python must match the reference.

| # | Service | What differs | Reference output | Python output | Why | Approved by | Date |
| - | ------- | ------------ | ---------------- | ------------- | --- | ----------- | ---- |
| 1 | `treegrafter` | The whole implementation: we adopt EBI's Python `treegrafter` instead of porting the legacy Perl 1.01 | Perl 1.01: HMMER, then RAxML 8.2.4 placement; 3-column output (query, family, annotation string) | EBI `treegrafter`: `hmmsearch`, then EPA-ng placement; TSV of up to 15 columns (subfamily, scores, coordinates, graft node, optional GO) | EBI maintains it for InterPro, it targets current PANTHER releases (the Perl hardcodes PANTHER 12), and it's Apache-2.0. Its output becomes the parity reference. Decided by the team on 2026-10-28 | | |
| 2 | `csnp` | Start node of the trace-back (`SCORE-2`) | Last `.paml` header match, often an internal node whose label collides with the leaf's: `del28` gives `470,probably damaging,0.57` | The gene's own leaf column (first match below the root): `del28` gives `797,probably damaging,0.74` | Wrong start node for 17.4% of leaves in the library. Proposed in the cSNP parity review | | |
| 3 | `csnp` | Batch state (`SCORE-7`, `SCORE-8`) | State leaks between SNPs: results depend on input order, and a gene missing from the tree inherits the previous SNP's start node | Fresh state per SNP. A gene missing from the tree gives "Not scored". The sample in input order is unchanged, and the reversed order then matches it | Order dependence changes 9 of the 35 sample results. Proposed in the cSNP parity review | | |
| 4 | `csnp` | pDel bounds (`SCORE-6`) | `age < bound`: `del14`, `del19`, `del25` (age 91) get 0.19 | Inclusive bounds, as in the PI's table: 0.17 | The source table in `pantherdb/features-bugs#23` has inclusive bounds. Proposed in the cSNP parity review | | |
| 5 | `csnp` | Position mapping (`MAP-4`) | The residue at the alignment start, and one right after a query-side gap, are never mapped: `e1` (`M1V`) gives "Invalid substitution" | Map by alignment column: `e1` is scored | Start-loss variants and residues after gaps can't be scored. Proposed in the cSNP parity review | | |
| 6 | `csnp` | Substitution parsing at the legacy endpoint (`CGI-2`, `CGI-3`) | `main`'s CGI scores nothing for `+`-joined input (what the website sends). The site's copy drops tokens containing `2` or `B` | Split on whitespace and `+`, decode properly, and report rejected tokens | Website requests return all their substitutions. Proposed in the cSNP parity review | | |

Not listed, because they don't change a correct single request's output: the command injection (`CGI-5`) and the shared temp file (`CGI-6`) in the cSNP CGI. They are never replicated. Still open, with no proposal to log: the thresholds (`SCORE-5`) and the species file (`DATA-3`). See the open questions in [tech-stack.md](../design/tech-stack.md#open-questions).

Quirk IDs refer to the cSNP legacy behaviour spec (`panther-workspace/legacy/cSNP_analysis/.specs/2026-10-28-legacy-behavior-spec.md`). Its §7 has the sample and edge-case inputs (`del1`–`del35`, `e1`–`e10`) these rows cite.
