# Divergences

Every deliberate difference between the Python engine and a service's reference. The format and rules are in [README.md](README.md). A row without an approver is a proposal: until it's signed off, the Python must match the reference.

| 8 | `csnp` | A query `blastp` can't read: it exits with status 1. | 9 | `refmap` | An unknown organism, or a missing or unreadable classification file (`REFMAP-9`) | Every ID is `NOHIT`, with no error: neither script checks that `open` succeeded (`map_panther.pl` 28, `genericMapping.cgi` 46) | An `organism` that isn't a 1-to-5-character code is a `422`, and no job; so, once the engine exports its organism list, is one not in it. | 10 | `refmap` | IDs the API rejects (`REFMAP-10`, and new rules): an empty ID, one with whitespace, one with a character outside printable ASCII, or one longer than 64 characters | One output line per such input line, with the ID as given and `NOHIT`, unless a classification file holds that exact ID. | 11 | `hmmscore` | The longest sequence taken: at most 10,000 residues, counting letters only, where the reference took 50,000. `PANTHER_API_HMMSCORE_MAX_RESIDUES` sets it, 10,000 by default and at most; a server that sets a lower value (#68) records it here, approved with it | The website's form took up to 50,000 characters after removing one header and whitespace (`SequenceSearchForm.java` 81 to 86), and scored them | A sequence of more residues than the limit is a `422` on `sequence`, naming the limit, and no job is created. A final `*` isn't counted | The product owner's starting limit, expected to cover 99% of queries. A 50,000-residue query needed 21 GiB at `--cpu 0` (`titin-50000`, [the survey](hmmscore-library-survey.md#alone)), and the limit bounds a job's time and memory. Raising it is the product owner's call. Proposed by `add-hmmscore-job` | Product owner | 2026-11-12 |
| 12 | `hmmscore` | Sequences the API refuses where the reference answered no hit (`HMMSCORE-6`, `HMMSCORE-8`, `HMMSCORE-10`): an empty one, or a header with no residues; one with a character other than a letter, except a single `*` at the end, so `-`, `.`, `_`, `~` and a `*` before the end included. With them, what the website's posting changed before the CGI saw it, and a header after a blank line | No hit: `hmmscan` refused the sequence, its exit status was ignored, and the table was empty (`pantherScore.pl` 381). Except `-`, `.`, `_`, `~` and an inner `*`, which 3.1b2 read as positions and split the hit: APOE with three inserted scored 667.1 bits in three domains, against 721.8 in one (engine developer, 2026-11-11). The posting cut the text at `&` and `=`, turned `+` into a space, decoded `%xx` and removed `<!--…-->`. A header after a blank line was left in, joined to the residues, so the CGI got one header line and no sequence | A `422` on `sequence` that doesn't contain the sequence, and no job. The header after a blank line is removed, as the API trims first, and the residues are scored | A no-hit answer says the sequence matches no family when it was never searched, or searched in pieces. HMMER 3.4, the port's, reads `.`, `_`, `~` and an inner `*` as one domain (708.5 bits for the insertions above) and refuses `-`, so neither refusing nor stripping them reproduces 3.1b2. Refusing before a job saves one that reads all of `binHmm.h3f` only to fail. Letters in either case, `B`, `J`, `O`, `U`, `X`, `Z` and a final `*` score alike in both (708.9 to 710.1 bits in 3.1b2, 709.1 to 710.3 in 3.4). Proposed by `add-hmmscore-job` | | |

Not listed, because they don't change a correct single request's output: the command injection (`CGI-5`) and the shared temp file (`CGI-6`) in the cSNP CGI, the unchecked `organism` in the refmap CGI's two-argument `open` (`REFMAP-8`), and `hmmscan`'s shared table in `pantherScore.pl` (`HMMSCORE-7`). They are never replicated. Batch state (`SCORE-7`, `SCORE-8`) doesn't arise in the service either: it scores one protein, so one family, per call, as the CGI did. Row 3 stays a proposal for batch use. Still open, with no proposal to log: the species file (`DATA-3`). Rows 4 and 7 follow the rule for legacy code and docs that disagree: the port follows the code, and the docs' version is revisited once the service is live on production (`CLAUDE.md`, `CONTRIBUTING.md`). See the open questions in [tech-stack.md](../design/tech-stack.md#open-questions).

The cSNP rows' quirk IDs refer to the cSNP legacy behaviour spec (`panther-workspace/legacy/cSNP_analysis/.specs/2026-10-28-legacy-behavior-spec.md`). Its §7 has the sample and edge-case inputs (`del1`–`del35`, `e1`–`e10`) these rows cite.

`REFMAP-` IDs refer to [refmap-legacy-behaviour.md](refmap-legacy-behaviour.md), whose `genericMapping.cgi` line numbers are RefProteomeMapper's `master`.

`HMMSCORE-` IDs refer to [hmmscore-legacy-behaviour.md](hmmscore-legacy-behaviour.md), whose line numbers are `pantherScoring/`'s at `89ea0ae` and `panther-site-java/`'s at `c0031ce`.
